# PRD feasibility and acceptance

The POC demonstrates a usable personal desktop library and a shared online web library. It demonstrates real storage, Rivto editing, concurrent browser updates and a tool approval crossing a process boundary. **The first-release acceptance criteria remain open.** In particular, the PRD requires offline edits to server workspaces, per-member access and live provider acceptance. Offline replicas and per-member access need implementation; the Mastra provider path needs a credentialed run. [Source PRD](../../dev_notes/chulane_prd.md) · [Architecture and proposed release boundaries](ARCHITECTURE.md)

## The fifteen acceptance scenarios

| PRD | What can be tried in this build | What remains for acceptance |
|---|---|---|
| 1. Local knowledge without registration | Launch desktop, create a workspace/project/page, edit with Rivto, search title/body and reopen after restart. All operations run locally. | Installer and restart checks on each target OS. An initial personal library is created automatically as a POC convenience. |
| 2. Server connection and membership | Web sign-in, multiple workspaces, and server-enforced editor/viewer roles. | Desktop remote profiles and combined workspace list, self-registration, invitations, owner/admin roles and per-workspace membership. Everyone holding a given key gets the same installation-wide role. |
| 3. Collaboration and offline editing | Independent online editors converge after competing writes; another browser can observe the result. Desktop local editing works without a remote dependency. | Durable offline server replicas, replay after restart, rejection/export on revocation, manual retry and presence controls. The POC cannot deliver unsent edits after a disconnected tab is closed. |
| 4. Workspace journal | **Open today** creates or opens one daily page per workspace/date in SQLite. | Workspace time zone, midnight rollover, continuous stacked days and cross-device offline reconciliation. The UI currently uses the device's calendar date. |
| 5. Tags and fields | A user can type a literal hashtag and find it by text search. | Workspace tag definitions, reusable typed fields, page/block applications, retained values, source links and sortable/filterable editable tables. |
| 6. Page and canvas | A mounted document switches between Rivto Page and Edgeless without replacing its editor. Rename and project move retain its database ID. Web tool links address that ID. | Nested projects, page-reference authoring and testing the stable block catalogue. Canvas interaction was checked at the surface-switch boundary; individual drawing tools need coverage. |
| 7. External and integrated agents | Real CLI and stdio MCP list workspaces/projects, search/read writing content, and propose creation/rename. Editor approval and role checks run in the service. The internal Mastra sidebar reads and edits page bodies with approval. | External clients still need named profiles, desktop pairing and per-user grants. |
| 8. Desktop plugins | Install a trusted local folder after seeing its path. Native command contributions follow Cordis enable/disable. The registration can be removed without deleting plugin files. | Renderer contributions and Rivto custom-block registration, unknown-block placeholders and restoration. Linux smoke exercises loading and disposal of the sample native command. |
| 9. Workspace lifecycle | Pages have recoverable trash with stable IDs, content and files. | Whole-workspace archive/restore, project-tree trash, tombstone propagation, admin-only purge and stale-replica recovery. |
| 10. Server backup | A Docker image serves the application. Cold copying the database restores documents, files and pending decisions. The data-directory procedure is documented. | A release backup includes real user accounts, membership, admin settings and schema/version upgrades as those capabilities land. Hosted-provider credential reconfiguration is still open. |
| 11. Real provider and citations | Search/read tools return page URLs and are consumable by a Harness MCP client. The published Harness executor discovers the search tool and returns a live source link without model credentials. The built-in Mastra sidebar streams replies, cites read pages, and proposes block edits. End-to-end checks exercised its OpenAI HTTP integration using a scripted provider. | A real provider-selected citation and edit require the credentialed acceptance check. |
| 12. Approval and restart | Proposals persist. Approval rechecks the role and page, applies one change and records the decision atomically. The database restore test rejects viewer approval and duplicate approval. | Per-author identity, policy for remembered grants, user-visible history of completed decisions and recovery for external tools with uncertain side effects. |
| 13. Arbitrary attachment | Store and download original bytes and filename on either host. Another authorized web session can retrieve the bytes. POC limit is 16 MiB per file. | Desktop caching of remote attachments, attachment extraction for retrieval, and durable handling of files across independent offline replicas. Use the host's **Attach** control for durable bytes. |
| 14. Markdown exchange | Import creates a new page with a new ID in the selected location. Export emits the writing projection and reports omitted canvas objects, attachments and properties. | Semantic Markdown conversion for all supported rich blocks, round-trip fidelity tests and automated coverage of third-party block warnings. |
| 15. Agent run lifecycle | A sidebar turn continues across document navigation, stops on window close, and persists its partial output and interruption status. | Independent background runs and recovery after revocation of an individual member. |

## Other PRD requirements

- **Deployment.** A real Linux Electron window and a web container were exercised. Electron makes macOS and Windows plausible targets, but installers, signing, updates and platform-specific behavior require separate builds on those systems. Android and a managed cloud service remain outside this POC.
- **Customization.** Navigation and native inputs have keyboard controls, labels and focus styles. The build has a fixed theme. User-authored themes, editor typography settings, plugin-driven toast delivery and an accessibility audit remain open.
- **Retrieval.** The current tool contract is workspace-scoped `search(query) → [{id,title,url}]` followed by `read(id) → {id,title,url,text}`. The host accepts a replaceable PageRetriever. Search and source reads each validate workspace and trash state. An integration test supplies a retriever returning stale, duplicate and foreign IDs and checks what reaches a viewer. Search uses literal case-insensitive matching over titles and the saved writing projection. Ranking, block-level citations, embeddings, file extraction and RAG evaluation require additional work. The backend must apply membership policy before any future retrieval step returns content.
- **Agent environments.** The POC exposes knowledge through MCP and supplies a runnable Harness Cordis overlay. Its built-in Mastra agent uses foreground host-side turns with scoped page tools. Background execution, isolated environments and plugin generation remain open. A real provider key is needed for live inference acceptance.
- **Scale and consistency.** One SQLite writer and full-state document transfers are sufficient to demonstrate the workflows. Page lists carry full writing text. No latency or library-size threshold has been established. Online metadata writes use the last accepted request. A conflict UI and a durable offline outbox are required for the PRD guarantees.
- **Security and distribution.** Keys are shared per installation and trusted desktop plugins execute with operating-system privileges. Per-user revocation, quotas, session expiry and TLS deployment are release work. Use separate installations for independent audiences. The Rivto submodule preserves the exact upstream source and history; redistribution rights need clarification before shipping installers.
- **Product decisions.** The PRD leaves metadata conflict resolution, purge retention, revoked-edit export format, invitation framework and performance thresholds open. The POC does not decide these by accident. Resolve them against real recovery scenarios before promising release behavior.

## Evidence and limits

| Check | Observed outcome |
|---|---|
| Clean POC dependency resolution and frozen install; TypeScript and production bundle | Succeeded with the POC lockfile. The renderer bundle is about 1.75 MB before gzip. Bundling and type checking do not validate every upstream extension. |
| SQLite/HTTP integration | Anonymous and viewer writes rejected at the boundary. A stale document PUT returned 409. A journal day was unique. A second service opened a copied cold database and recovered document bytes, original attachment bytes and a pending proposal. Approval executed exactly once. |
| Chromium, independent sessions | An editor created and edited a page, switched surfaces and recovered it after reload. A viewer read it. Two editors writing against the same base revision converged. An actual stdio MCP search returned a navigable source, and a proposed page was created after browser approval. Markdown import/export controls, attachment upload, page trash and restoration were also exercised. |
| Published DeepSeek Harness 0.2.2-rc.5 | The Web profile loaded the Cordis patch, discovered Chulane over stdio MCP and executed a search against a disposable workspace. The smoke asserts the source title, ID and link. It uses a programmatic tool invocation. Model selection and inference still need a provider test. |
| Electron on Linux | A real window started its local host, wrote a page and reopened the content after a process restart with the same temporary user-data directory. A sample native plugin command appeared on installation and disappeared on disable. Native chooser/consent responses were supplied by the smoke test. |
| Docker | Built the image and launched it on a disposable port. The running container served the renderer, accepted a login and returned the SQLite-backed library. The packaged Mastra runtime also streamed and persisted a reply using a local provider fixture. A second container restored a cold copy of the first data directory and found the saved page by its writing text and downloaded its original attachment bytes. |
| Mastra sidebar | Chromium and Linux Electron exercised real Mastra tool calls against a local scripted OpenAI HTTP endpoint. The checks cover same-page undo, cross-page edits, stale proposals, view-only history on web, interrupted streams and rejected provider keys. A cold-restart integration test checks recovered pending approvals and duplicate application. A separate protocol fixture verifies that a Codex model ID uses the Responses endpoint with the page tools. |
| Outside this run | Windows/macOS installation, Firefox/Safari, model-driven provider inference, full Rivto regression suites, production load/security testing and a general accessibility audit. The isolated POC has no lint task. |

For repeatable commands and the precise assertions, see the [runbook](README.md), [storage checks](tests/integration/server.test.ts), [workspace and CLI checks](tests/integration/workspace.test.ts) and [rendered smoke checks](tests/e2e/hosts.spec.ts).
