# PRD feasibility and acceptance

The POC demonstrates a usable personal desktop library and a shared online web library. It demonstrates real storage, Rivto editing, concurrent browser updates and a tool approval crossing a process boundary. **The first-release acceptance criteria remain open.** In particular, the PRD requires offline edits to server workspaces and per-member access. Claude Code 2.1.330 rejected a signed-out connection, recognized an isolated API-key configuration, and completed a two-step Chulane search against a loopback Anthropic Messages fixture. The installed Hermes 0.21.5 CLI also completed a two-step search with a scripted loopback model, returning an intermediate message and a final reply from the tool result. The live local Codex acceptance run exercised a cited lookup through the Chromium sidebar and a reviewed cross-page edit. The API-backed Mastra path has separate fixture coverage. ## The fifteen acceptance scenarios

| PRD | What can be tried in this build | What remains for acceptance |
|---|---|---|
| 1. Local knowledge without registration | Launch desktop, create a workspace/project/page, edit with Rivto, search title/body and reopen after restart. All operations run locally. On Ubuntu 24.04 amd64, dpkg installed the desktop package into a temporary root. Its sandboxed executable created a workspace and page, saved an edit and reopened it after restart from outside the checkout. | Installer validation and equivalent restart checks on macOS and Windows. |
| 2. Server connection and membership | Web account registration and private owner workspaces. Electron groups local and remote workspaces in one picker and opens the selected server in an isolated session. The two-server Linux test covers editing, account isolation and saved addresses after restart. Owners can change existing members’ roles and revoke access. Concurrent removals preserve one owner. | Server administrators are bootstrapped on the host and can manage self-registration. Username invitations to registered accounts survive restart and grant membership only after acceptance. Chromium exercises owner invitation and recipient acceptance. Linux Electron exercises the owner workflow on a remote server. Registration by invitation for a new account remains open. |
| 3. Collaboration and offline editing | Independent online editors converge after competing writes; another browser can observe the result. A named-account Electron user can edit a previously opened remote document while disconnected, restart offline and merge its pending edits after sign-in, including an independent server edit. With an expired session the desktop sign-in screen also offers the previously opened workspace for offline editing. Other pending pages in the reopened workspace replay without opening their editors. Queued document edits and title changes can sync while a page is in Trash, including Trash inherited from a project. Divergent titles remain available for review after restoration. Trashing an individual page or project checkpoints its accepted live drafts. A production web host received a live Chromium edit, handled SIGTERM, and reopened the edit and its searchable text after restart. An HTTP regression also kills the host after two acknowledged live revisions and reopens both the crashed database and an online backup. Both recover the latest document bytes and writing text. A fresh Chromium session also reopened the exact paragraph after a production host was killed between its live acknowledgement and its ordinary save. Electron also verifies a rejected upload with an online catalog, a visible sync error, and manual delivery after the affected page closes. After membership removal, the account can export its pending Yjs document as recovery JSON or download Markdown for import into another workspace. Electron verifies the download, the server copy and workspace cache removal. Offline page titles survive a desktop restart, reconcile with competing online titles and remain exportable after revocation. A retried rename cannot reopen a resolved conflict. | Desktop queues page titles, page moves and project renames. Other offline metadata changes and presence controls remain open. |
| 4. Workspace journal | Each workspace stores its journal time zone. An open journal creates the workspace day on its next refresh, even when a viewer opens it first, stacks editable days in date order and reuses existing page IDs. Navigation checkpoints all mounted days. Named owners can change journal settings on web. Offline desktop clients resolve the date in the workspace time zone and can edit downloaded days. HTTP integration merges two independently initialized daily documents and a server edit into one page and one paragraph. Two isolated Electron profiles authored the same new day offline. One reopened its draft after restart. After both signed back in, the server contained one page with both edits and its independent paragraph. The following blank day also synced. | The two-device workflow has been exercised on Linux Electron. macOS and Windows runs remain open. |
| 5. Tags and fields | Create or complete a workspace tag while typing in a block, apply tags to whole pages or individual blocks, and open sources from the tag list. Edit text, numeric, calendar date, checkbox and single-choice fields in the sortable, filterable tag table. Shared definitions retain separate values per tag and object across detachment and restoration. Chromium and Linux Electron select an existing accented tag when typed in decomposed form and offer to restore it by name from Trash. The page picker retains combining marks in suggestions such as #क्षेत्र. | On Linux Electron, downloaded page and block tag sources remain navigable after an offline restart. Pending writing and title edits appear in these sources. The read-only field table supports sorting, filtering and navigation for downloaded sources. Changing tags and field values requires connectivity. |
| 6. Page and canvas | A mounted document switches between Rivto Page and Edgeless without replacing its editor. Rename and project move retain its database ID. Page references use persistent IDs, display current titles and open from both surfaces. SQLite backups retain the relationships. | The host check converts a paragraph to a native Rivto task, edits its status and fields, switches surfaces and reopens the page to verify the block ID and saved values. The same check inserts Table, Columns, Kanban and Bento through the slash menu and verifies their identities after reopening. It also verifies saved table-cell text, a column paragraph and a Kanban card. The canvas text tool is exercised by placing a label, editing it, searching for it and reopening the canvas. Chromium and Linux Electron also move an existing paragraph into Bento, edit it and resize its tile using the keyboard. After switching surfaces and reopening the page, the paragraph retains its ID, text and preferred width. Other canvas drawing tools still need host coverage. |
| 7. External and integrated agents | Named CLI and stdio MCP connections select a server, workspace and credential, authenticate with a shared key or server account, identify the requesting account in review and history, list workspaces/projects, search/read writing content, and propose creation, rename or a checked paragraph edit. CLI and MCP can browse a project one level at a time, including paginated page IDs. Both can follow a search offset directly into a writing block or canvas, read a bounded passage, and return a link to its source. An external creation request can carry a destination project and Markdown. Review shows both, and approval creates the editable page after rechecking the project and requester. Editor approval and role checks run in the service. Signed-in Codex browsed a parent folder and proposed renaming the requested nested project. Approval preserved its ID and child page, and a same-name project at the root kept its name. The internal sidebar supports read-only turns, reviewed block edits and reviewed page renames, and drafting new Markdown pages into a selected project with API or installed agents. A rename checks the page title again at approval. Authors and owners can delete a shared conversation. Removal stops its running response, clears its reviews and removes the transcript from other open sessions. | Desktop pairing and per-user grants. |
| 8. Desktop plugins | Install a trusted local folder after seeing its path. Cordis owns native commands and renderer modules. The local editor adds a plugin block through its slash command, uses Rivto’s placeholder after disable or removal, and reopens the same block for editing after reinstall. | Linux Electron also reopens saved blocks with an enabled plugin folder missing, displays the startup error in the native menu, and restores editing after the folder is repaired and retried. Equivalent macOS and Windows checks and a compatibility policy for changed block schemas remain open. |
| 9. Workspace lifecycle | Pages and nested project trees have recoverable trash with stable IDs. Restoring a tree preserves earlier independent deletions. Desktop and named web owners can archive and restore whole workspaces across restarts. | Owners can permanently delete a trashed page. The server retains its ID and journal date, removes its content and attachments, and dismisses pending proposals. Linux Electron exercised export of a permanently deleted page with an unsynced paragraph and an opaque attachment, and a second page with only its synchronized copy. Cancelling discard preserved the copy for export. Owners can mark archived local and named-server workspaces for deletion. Administrators can recover or purge them without acquiring membership. Purged IDs stay retired. Remote desktop edits saved before a restoration remain queued for explicit per-page sync or export. Retention policy remains open. |
| 10. Server backup | A Docker image serves the application. The snapshot command captures committed workspace data while the service runs. The Electron File menu can save all local workspaces and a fresh desktop profile can reopen their documents, attachments and chats. A separate Docker deployment restored an account, owner membership, workspace time zone, writing content and original attachment bytes. The original provider key was absent. Integration checks also cover archived status and pending decisions. | Administrator identity and registration policy survive restore. The administrator can restore the shared provider credential in Server settings. Legacy flat workspaces upgrade to format 2. The verifier and host reject a newer format before migration. A format-1 snapshot restored an editable page on an independent Docker data directory, and the native backup reopened a document, attachment and chat in a fresh Linux Electron profile. A backup from an unversioned Docker deployment reopened on a fresh format-2 volume with its CSV searchable and byte-identical. Linux Electron reopened a format-1 profile created by the earlier packaged app and found its CSV after upgrade. |
| 11. Real provider and citations | Search/read tools return page URLs and are consumable by a Harness MCP client. The published Harness executor discovers the search tool and returns a live source link without model credentials. The built-in Mastra sidebar streams replies, cites read pages, and proposes block edits. Its text-range tool can continue through long blocks and canvas labels. A reviewed block replacement requires a contiguous read of the complete text. Saved citations survive source removal and report an unavailable target when followed. Chromium also checks that opening a block URL in a new document view scrolls to the target or reports a missing block. End-to-end checks exercised the OpenAI HTTP integration using a scripted provider. | Starting without an open page, the Chromium sidebar used the installed Codex login to find a random station identifier published by a second open editor. The saved catalog still held the previous paragraph when the lookup began. Codex read the receipt code beyond the first 12,000 characters and cited the matching block. On request, live Codex opened the matching page directly in the initiating Chromium window and answered with the receipt code and a citation. An identically titled page in a separate account stayed inaccessible. A live Codex turn searched for a unique phrase in two long blocks on the same page, returned the separate receipt beyond each search excerpt and cited both block IDs. The live local Codex acceptance check also selected the requested nested project’s page, produced a cited edit, and left a root page with the same title untouched. A second turn proposed a page title change that took effect only after approval and preserved the page text. After a host restart and 13 intervening turns, live Codex recovered a block from its own earlier answer and quoted the revised receipt despite an identically titled page. In a separate test after 13 unrelated turns, live Codex recovered an earlier user-linked block from the same conversation, read its receipt code and cited the correct source among three identically titled pages. Live Codex also drafted a new page using the current document’s date in the requested nested project. The page appeared only after approval. Active agent turns recheck membership on removal or role change. |
| 12. Approval and restart | Proposals persist. A signed-in Codex turn encountered a concurrent paragraph replacement, reread the block and submitted one updated proposal. Chromium and Electron also exercised the conflict during a Mastra turn and applied the new proposal. Approval checks both the reviewer and the initiating member of the turn. Document and project changes commit with their review decision. Live Codex looked up an applied page proposal after 13 intervening turns and cited the renamed page by its recorded ID while a second page had its original title. Pending page and project previews follow the destination folder ID through ancestor renames. Approval checks the displayed path and retains both requested and accepted paths when they differ. A role downgrade or removal blocks a pending change, including after server restart. Shared chats identify named prompt authors and reviewers. External decision history identifies the requester and reviewer and links to the result. The database restore test rejects viewer approval and duplicate approval. | Policy for remembered grants and recovery for external tools with uncertain side effects. |
| 13. Arbitrary attachment | Store and download original bytes and filename on either host. A cold restore preserves leading and trailing spaces, decomposed Unicode and punctuation in the attachment record. Chromium uses the stored filename when downloading through a differently labeled editor link. Another authorized web session can retrieve the bytes. A named-account Electron client caches acknowledged uploads and downloaded bytes. It shows device availability, downloads an opaque file after an offline restart, and drops cached files when membership is revoked. Agent search returns excerpts and downloadable citations from UTF-8 text, Markdown, CSV and TSV attachments. Signed-in Codex found two matching files on the same page, quoted a different random seal beyond the search excerpt in each, and linked to both original downloads. Sidebar, CLI and MCP search results include the Unicode character position of the match. All three clients can read from that position with workspace access checks. CLI and MCP return separate links to the page and the original file. A named-profile CLI test verifies the file URL in a second workspace and checks authentication on download. | 14. Markdown exchange | Import creates a page of editable Markdown blocks in the selected project. An integration test runs a replaceable background environment and checks tool revocation and shutdown cleanup. OS isolation remains open. |

## Other PRD requirements

- **Deployment.** An Ubuntu amd64 desktop package and a web container were exercised. Codex discovery resolved the Windows x64 and Arm64 executables from the published 0.171.0 npm packages on Linux. The Windows-native connection check still needs a Windows host. A Linux build host can generate a per-user Windows x64 NSIS installer from the pinned Windows Electron distribution. The extracted executable matched the pinned x64 Electron binary byte for byte. The extracted application files passed the edit and restart check with Linux Electron. The identical payload completed the Mastra sidebar and local CLI fixture checks on Linux. Windows installation, restart and uninstall still need a native test. Mac packaging produces separate Apple Silicon and Intel application archives. Both Linux cross-builds were extracted and checked for executable architecture, framework links and runtime notices. Both contained the same application files that passed workspace restart and agent sidebar tests under Linux Electron. Running the native signing and installed-app checks on macOS, distribution signing, notarization and updates remain open. Android and a managed cloud service remain outside this POC.
- **Customization.** Navigation and native inputs have keyboard controls, labels and focus styles. A device-local appearance dialog saves application colors, typeface and size with independent editor settings. Plugin-driven toast delivery and a full accessibility audit remain open.
- **Retrieval.** The current tool contract is workspace-scoped `search(query) → [{id,title,url}]` followed by `read(id) → {id,title,url,text}`. The host accepts a replaceable PageRetriever. Search and source reads each validate workspace and trash state. An integration test supplies a retriever returning stale, duplicate and foreign IDs and checks what reaches a viewer. Library search always uses literal matching and returns all matching pages, including attachment-only matches. Agent retrieval can rank results independently and returns up to 30 sources. The default retriever uses literal case-insensitive matching over titles, writing text, canvas labels and extracted attachment text. Online search and tool reads include the latest host-published draft. A viewer can follow a matching live block while another editor continues typing. Changed and previously unindexed canvas labels are derived from the saved Rivto state on the next workspace search. A canvas match supplies an excerpt and a citation that opens the document in Canvas view. Truncated block and canvas search hits include a UTF-16 offset for a direct passage read. The agent can read beyond the preview and retains the matching citation. Library search groups every matching file under its page, with an excerpt and a download for each file. Agent search prioritizes one result per ranked page before filling its remaining slots with additional sources. Offline desktop searches scan the authorized cached page snapshots, merge pending writers and search downloaded UTF-8 text, Markdown, CSV and TSV attachments with the same extraction and excerpt rules as the server. File citations use the original filename. Online-only file contents are absent from the device results. Online-only pages retain their catalog search and availability status. Large-library latency is unmeasured. For a ranked writing match, the host returns the matching Rivto block ID with up to 320 characters of context. Agent search can also return additional matching blocks and a matching canvas passage on the same page, within its 30-result limit. The library, chat and external tool links can open that block. Text-only pages keep page-level links until they have stable editor IDs. Multi-passage ranking, embeddings, additional extractors and RAG evaluation require additional work. The backend must apply membership policy before any future retrieval step returns content.
- **Agent environments.** The POC exposes knowledge through MCP and supplies a runnable Harness Cordis overlay. Its built-in Mastra agent uses foreground and background host-side turns with scoped page tools. The host accepts a background execution environment with turn-scoped tools, cancellation and cleanup. The default runs in process. In a local desktop workspace, write-capable agent turns can draft native and renderer module source. The sidebar persists the draft for review and offers a native folder chooser and installation confirmation. OS isolation remains open. A real provider key is needed for live inference acceptance.
- **Scale and consistency.** One SQLite writer and full-state document transfers are sufficient to demonstrate the workflows. Page lists carry full writing text. No latency or library-size threshold has been established. Concurrent online page moves retain distinct destination IDs, including the workspace root. Concurrent online project renames retain distinct alternatives. The Chromium test resolves a conflict from the project view and verifies that the child project follows the selected name. Documents, page titles, page moves and project names share a device outbox. Other offline metadata mutations and their conflict handling remain open.
- **Security and distribution.** Keys are shared per installation and trusted desktop plugins execute with operating-system privileges. Per-user revocation, quotas, session expiry and TLS deployment are release work. Use separate installations for independent audiences. The Linux package is built locally. The Rivto submodule preserves the exact upstream source and history; redistribution rights still need clarification before publishing installers.
- **Product decisions.** The PRD leaves metadata conflict resolution, purge retention, the final recovery interchange format, invitation-based registration and performance thresholds open. The POC does not decide these by accident. Resolve them against real recovery scenarios before promising release behavior.
